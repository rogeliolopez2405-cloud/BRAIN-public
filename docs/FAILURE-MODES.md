# Failure-mode map

Seventeen ways a durable world model goes wrong, what BRAIN does about each, where the proof
is, and what is still open. Run any `attack.mjs` command to watch the row happen.

| Failure mode | What can go wrong | BRAIN mechanism | Test / proof | Remaining limit |
|---|---|---|---|---|
| **Process crash** | The process dies mid-action; the retry either repeats a consequential act or abandons one that succeeded. | Write-ahead journal: the intention is recorded before the act, so a dead process leaves a readable intention rather than silence. `recoverAction` returns a verdict, never a guess. | `tests/actioncontinuity.test.mjs`, `tests/commitment.test.mjs`<br>`crash-recovery` (attack id; tooling not published — see [VALIDATION-RESULTS.md](../VALIDATION-RESULTS.md)) | At-most-once, not exactly-once. A dispatch that fails on the wire leaves the action unperformed and says so. |
| **Lost acknowledgement** | The far side did it; the answer never came back. Treating that as failure repeats it; treating it as success invents a fact. | `SENT_UNKNOWN` is its own state. TIMEOUT IS NOT NOT-EXECUTED, and its mirror: sent-without-an-answer is not verified. | `tests/commitment.test.mjs` test 16<br>`sent-unknown` (attack id; tooling not published — see [VALIDATION-RESULTS.md](../VALIDATION-RESULTS.md)) | Resolving it requires asking the far side. BRAIN cannot make the far side answer. |
| **Stale resumed context** | A session continues on what was true when it started. | `contextBasis` records what was relied on; `reconcile` re-checks each item against the current world and reports what moved. | `tests/resumption.test.mjs`, `tests/reconcile.test.mjs`<br>`resumed-context` (attack id; tooling not published — see [VALIDATION-RESULTS.md](../VALIDATION-RESULTS.md)) | Reconciliation reports; it does not decide what to do about a superseded assumption. |
| **Duplicate evidence** | The same record arrives twice and looks like two. | Union keyed by durable record identity. Re-importing is idempotent. | `tests/partition.test.mjs` | Two *different* records under one id are quarantined, not merged — a conflict, not a resolution. |
| **Same-root reread** | One source read twice, presented as two agreeing sources. | `supportFor` counts independent ROOTS via `rootsOf`, not reports. An unattributed report makes the whole structure UNKNOWN. | `tests/provenance.test.mjs`, `tests/evidenceidentity.test.mjs`<br>`same-root` (attack id; tooling not published — see [VALIDATION-RESULTS.md](../VALIDATION-RESULTS.md)) | Depends on records declaring lineage. A source that lies about its lineage is believed. |
| **Clock skew** | A writer with a fast clock wins every comparison. | Event time is separate from write time; a claim carries `occurred_at` distinct from `at`. Merge is order-invariant, so a fast clock cannot become world order. | `tests/temporal.test.mjs`, `tests/worldtime.test.mjs`, `tests/partition.test.mjs` | BRAIN has no trusted clock. It records what was claimed and keeps the two times apart. |
| **Late event** | Something that happened earlier arrives later. | Ordering is by event time, not arrival. A late record takes its place in world order. | `tests/backfill.test.mjs`, `tests/asof.test.mjs` | A late record that names no event time cannot be placed, and is reported as unorderable rather than appended to the end. |
| **Conflict** | Two origins disagree and the system picks one. | `CONFLICTING` is a first-class answer with no value attached. With no registered authority for the key, BRAIN refuses to choose. | `tests/contradiction.test.mjs`, `tests/truth.test.mjs`<br>`node tools/demo-world.mjs` step 4 | A conflict blocks a present-tense answer. Something has to register an authority or record better evidence. |
| **Partition** | Two worlds diverge with no contact. | Both sides keep writing; nothing is lost, because nothing depends on being reachable. | `tests/partition.test.mjs` | Availability is preserved at the cost of at-most-once for one-time grants. |
| **Rejoin** | Arrival order silently decides truth. | Union by identity; the merge decides nothing and imports no resolver. Byte-identical results from four merge orders. | `tests/partition.test.mjs`<br>`partition-conflict` (attack id; tooling not published — see [VALIDATION-RESULTS.md](../VALIDATION-RESULTS.md)) | Merge preserves conflicts. It does not resolve them, and cannot. |
| **One-time permission split** | The same grant is spent on both sides of a partition. | Exclusive create (`flag: 'wx'`) gives at-most-once *within* a world. Across a partition, both consumptions are reported intact after rejoin. | `tests/authorityrace.test.mjs`<br>`split-grant` (attack id; tooling not published — see [VALIDATION-RESULTS.md](../VALIDATION-RESULTS.md)) | **DETECTION, NOT PREVENTION.** Prevention requires coordination before the partition. |
| **Concurrent knowledge change** | A held answer is used after the world corrected it. | Reuse revalidates against a dependency-scoped basis at use time; a real cross-process race reports `SUPERSEDED` and refuses reuse. | `tests/knowledgerace.test.mjs`<br>`concurrent-correction` (attack id; tooling not published — see [VALIDATION-RESULTS.md](../VALIDATION-RESULTS.md)) | Corroboration strength is not in the fingerprint. |
| **Authority revocation race** | A permission is checked, revoked, then used. | The lane decision is re-taken at send time rather than carried from an earlier check. Proven with a real cross-process handshake, and with a counterfactual that *does* send when handed the stale snapshot. | `tests/laneintegration.test.mjs` tests 21–22 | The window between revalidation and the socket is not zero; it is small and unexploitable by the tested path, not provably zero. |
| **Provider disappearance** | Removing an adapter changes what BRAIN believes. | Truth resolution imports no provider. Capability presence is observed and reported separately from truth. | `tests/amputation.test.mjs`, `tests/capabilityindependence.test.mjs` | BRAIN loses the ability to *learn* new external facts and says so. |
| **Lane violation** | Private data leaves under a policy that did not permit it. | `egress()` decides before the socket opens; a denial is zero bytes at a real HTTP sink. Fails closed with no policy. | `tests/laneenforcement.test.mjs`<br>`lane-zero-byte` (attack id; tooling not published — see [VALIDATION-RESULTS.md](../VALIDATION-RESULTS.md)) | Runs on **declared** provenance. Mislabelled data is released per its label. |
| **Transitive tool bypass** | A nested call inherits an ambient permission the direct call would not have got. | The policy travels with the call; there is no ambient state. Denied at depth 1, 2, 4 and 8. | `tests/laneenforcement.test.mjs`<br>`transitive-deny` (attack id; tooling not published — see [VALIDATION-RESULTS.md](../VALIDATION-RESULTS.md)) | Covers code that routes through the gate. |
| **Malicious in-process adapter** | Adapter code ignores the gate and opens its own socket. | **None. This is the boundary.** The gate governs code that asks it. | `tests/laneenforcement.test.mjs` test 24 (bypass demonstrated deliberately)<br>`malicious-adapter` (attack id; tooling not published — see [VALIDATION-RESULTS.md](../VALIDATION-RESULTS.md)) | Containment requires an OS boundary: a separate process with no network access, a container, a namespace, a firewall rule, or a capability-based runtime. |

---

Every "remaining limit" above is either a stated limitation in
[LIMITATIONS.md](../LIMITATIONS.md) or a property BRAIN never claimed. If you find one that is
neither, that is a documentation defect and worth reporting.
